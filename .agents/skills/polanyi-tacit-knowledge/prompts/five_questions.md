# Five Questions Method — 默会知识五问提取法

> 来源：Agent Factory / Panaversity
> 原文：https://agentfactory.panaversity.org/docs/Domain-Agent-Workflows/the-knowledge-extraction-method/the-five-questions

## 五问核心原理

Michael Polanyi："我们知道的比我们能说出来的更多。"

Five Questions Method 的核心洞察：**问"规则"不如问"案例"。**
专家说不出规则，但能讲案例。从案例中可以提炼出规则。

---

## Q1：成功案例提取

**问：** 给我讲一个这件事做得很好的近期案例——从头到尾完整讲一遍。

### 提取维度

| 字段 | 描述 | 追问 |
|------|------|------|
| 背景 | 什么情况触发了这个判断？ | 还有其他背景吗？ |
| 判断 | 当时怎么决定的？ | 犹豫过吗？想了多久？ |
| 结果 | 后来怎么样了？ | 好的结果让你确认了什么？ |
| 原因 | 为什么这样做是对的？ | 支撑这个判断的底层逻辑是什么？ |

### 格式模板

```
### 成功案例-{N}

背景：[]
判断：[]
结果：[]
原因：[为什么这样做是对的]
提炼规律：[一句话提炼这个案例中的核心判断模式]
```

### 追问话术

- "当时是什么让你觉得这样做是对的？"
- "这个判断是在多短时间内做出的？"
- "有没有犹豫过？还是直接就知道？"
- "如果要教一个新人，会怎么描述这个判断？"

## Q2：失败案例提取

**问：** 现在讲一个，这件事没做好的例子——哪里出了问题？

### 提取维度

| 字段 | 描述 | 追问 |
|------|------|------|
| 背景 | 什么情况？ | 还有其他背景吗？ |
| 判断 | 当时怎么决定的？ | 为什么这样决定？ |
| 问题 | 哪里出错了？ | 最关键的失误是什么？ |
| 原因 | 为什么会错？ | 根本原因是什么？ |

### 格式模板

```
### 失败案例-{N}

背景：[]
判断：[]
问题：[]
原因：[根本原因——为什么会错]
教训：[如何避免同类错误]
对应原则：[这个案例对应哪条默会原则]
```

### 追问话术

- "重来一次，你会怎么调整？"
- "新手通常在哪里犯错？"
- "有没有一个'时刻'，如果抓住就能避免？"
- "这个错误是因为缺少什么信息，还是判断框架有问题？"

## Q3：专家 vs 新手差异

**问：** 做这件事，初级和资深的人有什么区别？资深的人"看到"了什么新手机不会注意到的？

### 提取维度

| 维度 | 描述 |
|------|------|
| 资深判断 | 资深的人能看到什么？ |
| 新手遗漏 | 新手只能看到什么？ |
| 判断速度 | 资深的人用了多久做出这个判断？ |
| 可教性 | 这个差距能教给新手机器吗？ |

### 格式模板

```
### 专家 vs 新手判断差异

资深→[他们能看到/判断什么]
新手→[他们只能看到/判断什么]
差距层次：[在哪个层面产生差距]
判断速度：[资深用了多久——瞬间/几分钟/需要思考]
可教性：[这个差距能教给 AI 吗？能教多少？]
```

### 追问话术

- "这个判断能在多短的时间内完成？"
- "有办法把这个'看得出来'教给一个新手机器吗？"
- "资深的人和新人最关键的差距在哪一层？"
- "如果让新人也看同样的内容，他们会注意什么不同？"

## Q4：核心操作原则

**问：** 给一个要做这个决定的人写一页指南——如果只能告诉他三件事，是什么？

### 提取维度

| 要素 | 描述 |
|------|------|
| 原则内容 | 具体应该怎么做 |
| 适用条件 | 在什么情况下这条原则适用 |
| 边界情况 | 什么条件下这条原则不适用 |
| 优先级 | 如果只能选一条，最核心的是哪条 |

### 格式模板

```
### 原则一：{名称}

适用条件：[在什么情况下这条原则适用]
核心内容：[具体应该怎么做]
边界情况：[什么条件下不适用]
优先级：[核心/重要/参考]

### 原则二：{名称}
...

### 原则三：{名称}
...
```

### 追问话术

- "有没有边界情况？什么条件下这三条就不适用了？"
- "如果只能选一条，最核心的是哪条？"
- "有什么错误是很多人觉得没问题但其实错的？"
- "这三条原则中，哪条最难做到？"

## Q5：自动化红线

**问：** 在什么情况下，这件事绝对不能交给自动化系统，只能人来做？

### 提取维度

| 类别 | 描述 |
|------|------|
| 🚫 绝对红线 | 绝对不能自动化的场景 |
| ⚠️ 人工复核 | 可以自动化但必须人复核的场景 |
| ✅ 安全自动化 | 可以安全交给 AI 的场景 |

### 格式模板

```
### 🚫 永远不要自动化

[场景描述]
原因：[为什么不能自动化]

### ⚠️ 必须人工复核

[场景描述]
复核要点：[AI 处理时需要人检查什么]

### ✅ 可以安全自动化

[场景描述]
自动化条件：[在满足什么条件时可以自动化]
```

### 追问话术

- "有没有任何 AI 可以处理的层级？"
- "人和 AI 合作的话，各自负责什么部分？"
- "当你不确定的时候，你通常怎么决定？"
- "有没有一些情况，AI 做得比人还好？"

## 提取完成检查表

完成五问后，确认：

- [ ] Q1 至少 3 个成功案例
- [ ] Q2 至少 2 个失败案例
- [ ] Q3 专家 vs 新手差距已提炼
- [ ] Q4 至少 3 条核心原则
- [ ] Q5 自动化边界已明确
- [ ] 每个案例都有"提炼规律/教训"

## 案例质量判断

好的案例特征：
- 有具体情境（不是"一般来说"）
- 有可辨识的判断时刻
- 有可验证的结果

差的案例特征：
- 过于抽象（"要看情况"）
- 没有明确的判断时点
- 无法提炼出可操作的原则

遇到差的案例时：追问"能不能给一个具体例子？"
