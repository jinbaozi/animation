# 质检执行机制

## 一、概述

本文档定义了AI漫剧项目的质检执行机制，包括触发规则、多层检查流程、分级处理标准。

---

## 二、触发规则

### 2.1 触发时机

| 触发点 | 触发条件 | 触发内容 |
|--------|----------|----------|
| 阶段完成时 | 责任角色提交交付物 | 自动启动自检 |
| 交付物移交时 | 上游向下游交付 | 启动下游验收 |
| 阶段结束时 | 所有角色交付完成 | 质检合规官抽检打分 |
| 最终交付前 | 项目协调员确认 | 完整质检报告 |

### 2.2 触发流程

```
阶段N完成
    ↓
责任角色提交交付物
    ↓
【第一层】自检触发 ──→ 勾选检查清单
    ↓
核心项全部通过？
    ├── 否 → 返回修改
    └── 是 → 进入下游验收
              ↓
         【第二层】下游验收 ──→ 检查交付物完整性
              ↓
         交付物完整？
              ├── 否 → 退回上游修改
              └── 是 → 继续下一阶段
                        ↓
                   阶段N结束？
                        ├── 否 → 继续执行
                        └── 是 → 启动质检抽检
                                  ↓
                             【第三层】质检抽检 ──→ 执行打分
                                  ↓
                             打分≥阈值？
                                  ├── 否 → 退回责任角色修改
                                  └── 是 → 标记阶段通过
```

## 三、多层检查机制

### 3.1 第一层：输出前自检

#### 责任主体
- 各角色自己负责

#### 检查内容
- 对照《交付物检查清单》勾选
- 确认核心项全部完整
- 推荐项尽量完整

#### 检查方式
1. 打开《交付物检查清单》
2. 找到对应角色和交付物
3. 逐项勾选核心项
4. 核心项全部✅才可提交

#### 输出物
- 已勾选的检查清单截图/文档

#### 阻塞规则
- **核心项有❌**：禁止提交，必须修复
- **推荐项有❌**：可提交，但需标记缺陷

---

### 3.2 第二层：下游验收

#### 责任主体
- 接收交付物的角色

#### 验收关系

| 上游角色 | 下游角色 | 验收内容 |
|----------|----------|----------|
| 总导演 | 美术总监 | 结构化解析结果、分镜脚本、视觉意图输入 |
| 美术总监 | 技术主管 | 风格决策卡、人物卡、场景卡、分镜Prompt |
| 技术主管 | 质检合规官 | 一致性检查报告、基准图、参数配置 |
| 质检合规官 | 项目协调员 | 质量验收报告、打分结果 |
| 所有角色 | 项目协调员 | 最终交付物 |

#### 验收内容
1. 检查交付物是否齐全
2. 检查核心项是否完整
3. 检查格式是否符合模板

#### 验收方式
1. 对照《交付物检查清单》
2. 确认上游已勾选核心项
3. 检查实际内容与清单一致

#### 输出物
- 验收确认或退回说明

#### 阻塞规则
- **核心项缺失**：退回上游修改
- **格式严重不符**：退回上游修正
- **推荐项缺失**：接收但标记缺陷

---

### 3.3 第三层：质检抽检

#### 责任主体
- 质检合规官

#### 抽检时机
- 每阶段结束时
- 最终交付前

#### 抽检内容
1. 执行打分系统
2. 合规风险评估
3. 跨文档一致性验证

#### 抽检方式
1. 按《打分系统》对单镜/文档打分
2. 按《质检报告模板》输出报告
3. 更新《质检检查总表》

#### 输出物
- 质检检查总表
- 质量验收报告
- 打分结果

#### 阻塞规则
- **单镜<75分**：退回美术总监修改
- **文档<85分**：退回相关角色优化
- **合规高风险**：禁止发布

## 四、分级处理标准

### 4.1 交付物字段分级

| 级别 | 定义 | 缺失处理 | 修复时限 |
|------|------|----------|----------|
| **核心项** | 必须完整，影响流程衔接 | 阻塞流程，立即修复 | 2小时 |
| **推荐项** | 建议完整，影响质量 | 标记缺陷，限期修复 | 24小时 |
| **可选项** | 锦上添花，可后续补充 | 记录缺失，不阻塞 | 不限 |

### 4.2 核心项判断标准

判断为核心项的条件（满足任一）：
1. 下游角色依赖此字段才能开始工作
2. 缺失会导致最终输出严重不完整
3. 缺失会导致一致性控制失效

### 4.3 推荐项判断标准

判断为推荐项的条件：
1. 缺失不影响流程继续
2. 能显著提升输出质量
3. 是专业输出的标准组成部分

### 4.4 可选项判断标准

判断为可选项的条件：
1. 属于扩展功能
2. 缺失不影响核心质量
3. 可在后续迭代补充

### 4.5 处理流程

```
发现字段缺失
    ↓
判断字段级别
    ├── 核心项 → 阻塞流程 → 立即修复 → 2小时未修复则升级
    ├── 推荐项 → 标记缺陷 → 限期修复 → 24小时内修复
    └── 可选项 → 记录缺失 → 后续补充 → 不阻塞
```

## 五、质检检查总表

### 5.1 总表作用
- 一个表格跟踪所有质检状态
- 所有角色可见，透明化进度
- 作为最终验收依据

### 5.2 总表内容

| 板块 | 内容 |
|------|------|
| 阶段检查状态 | 各阶段的交付角色、自检、验收、打分、总体状态 |
| 核心项检查 | 各交付物的核心项检查结果 |
| 推荐项缺陷 | 推荐项缺陷列表 |
| 问题追踪 | 问题描述、责任人、状态 |

### 5.3 更新责任

| 更新时机 | 更新人 |
|----------|--------|
| 自检完成时 | 责任角色 |
| 验收完成时 | 验收角色 |
| 打分完成时 | 质检合规官 |
| 问题修复时 | 责任角色 |

## 六、退回修改流程

### 6.1 退回条件

| 触发层 | 退回条件 | 退回对象 |
|--------|----------|----------|
| 自检层 | 核心项不完整 | 禁止提交 |
| 验收层 | 交付物核心项缺失 | 上游角色 |
| 质检层 | 打分<阈值、合规高风险 | 相关责任角色 |

### 6.2 退回流程

```
发现问题
    ↓
记录问题到《质检检查总表》
    ↓
指定责任角色
    ↓
责任角色收到通知
    ↓
修复问题
    ↓
重新自检
    ↓
重新提交
    ↓
验收/质检复检
    ↓
通过则关闭问题
```

### 6.3 问题升级

| 情况 | 升级动作 |
|------|----------|
| 核心项2小时未修复 | 项目协调员介入 |
| 推荐24小时未修复 | 标记为遗留问题 |
| 同一问题返工3次 | 升级分析根因 |

## 七、质检通过标准

### 7.1 阶段通过标准

| 阶段 | 通过条件 |
|------|----------|
| 阶段1 | 自检✅ + 验收✅ |
| 阶段2 | 自检✅ + 验收✅ |
| 阶段3 | 自检✅ + 验收✅ |
| 阶段4 | 质检打分≥75（单镜）、≥85（文档） |

### 7.2 项目发布标准

| 条件 | 要求 |
|------|------|
| 所有阶段通过 | ✅ |
| 核心项全部完整 | ✅ |
| 单镜打分均≥75 | ✅ |
| 文档打分≥85 | ✅ |
| 无合规高风险 | ✅ |
| 推荐项缺陷已修复或标记 | ✅ |
