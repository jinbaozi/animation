# 迭代修订流程

---

## 一、概述

本文档定义AI漫剧项目的迭代修订流程，包括触发条件、修订流程、版本管理规范和统计分析方法。

---

## 二、修订触发条件

### 2.1 自动触发

| 触发场景 | 触发条件 | 触发动作 |
|----------|----------|----------|
| 质检不通过 | 单镜打分<75分或文档打分<85分 | 自动退回责任角色修改 |
| 核心项缺失 | 核心项检查有❌ | 禁止提交，要求立即修复 |
| 下游验收失败 | 交付物被下游退回 | 通知责任角色修改 |
| 合规高风险 | AI魔改/版权/敏感词风险为🔴 | 禁止发布，要求修改 |

### 2.2 人工触发

| 触发场景 | 触发人 | 触发条件 |
|----------|--------|----------|
| 需求变更 | 项目协调员 | 用户需求发生变化 |
| 风格调整 | 总导演/美术总监 | 需要调整视觉风格 |
| 技术优化 | 技术主管 | 一致性控制需要优化 |
| 质量提升 | 质检合规官 | 推荐项需要优化 |

### 2.3 触发流程图

```
触发条件满足
    ↓
记录触发原因
    ↓
判断严重程度
    ├── 紧急（阻塞流程） → 立即启动标准修订流程
    ├── 重要（影响质量） → 24小时内启动标准修订流程
    └── 一般（优化改进） → 计入待办，批量处理
```

## 三、修订流程

### 3.1 标准修订流程

```
Step 1：发现问题
    ├── 质检打分不通过
    ├── 验收发现缺陷
    └── 需求变更

Step 2：记录问题
    ├── 更新《质检检查总表》问题追踪
    ├── 指定责任角色
    └── 设定修复时限

Step 3：责任角色修改
    ├── 分析问题根因
    ├── 修改交付物
    └── 更新检查清单

Step 4：重新自检
    ├── 勾选核心项
    ├── 确认修改完整
    └── 标记修改内容

Step 5：重新提交
    ├── 提交修改后的交付物
    └── 通知验收方

Step 6：验收/质检复检
    ├── 验收方检查
    ├── 质检合规官打分
    └── 更新问题状态

Step 7：关闭问题
    ├── 验证通过
    ├── 更新版本记录
    └── 关闭问题追踪项
```

### 3.2 紧急修订流程

适用于阻塞流程的紧急问题（如核心项缺失、合规高风险）。

```
发现问题（紧急）
    ↓
立即通知责任角色（即时通讯）
    ↓
责任角色2小时内修复
    ↓
立即提交（跳过排队）
    ↓
质检合规官即时复检
    ↓
    ├── 通过 → 继续流程
    └── 不通过 → 返回修改

超时处理：
    ├── 2小时未修复 → 项目协调员介入
    └── 4小时未修复 → 升级至管理层
```

### 3.3 批量修订流程

适用于多个推荐项缺陷的批量处理。

```
收集推荐项缺陷
    ↓
按责任角色分组
    ↓
批量分配修改任务
    ↓
各角色并行修改
    ↓
批量提交
    ↓
统一验收
    ↓
更新质检检查总表
```

### 3.4 返工统计触发

| 条件 | 动作 |
|------|------|
| 同一问题返工3次 | 升级分析根因，考虑流程改进 |
| 同一角色返工5次 | 提供额外指导或调整分工 |
| 同一阶段返工率>30% | 评估该阶段流程合理性 |

## 四、版本管理规范

### 4.1 版本号格式

```
v[主版本].[次版本].[修订号]

示例：v1.2.3
- 主版本：重大变更，如风格切换、角色重设
- 次版本：功能变更，如新增镜头、修改Prompt
- 修订号：Bug修复，如修正错别字、调整参数
```

### 4.2 版本升级规则

| 变更类型 | 版本升级 | 示例 |
|----------|----------|------|
| 重大变更 | 主版本+1，次版本/修订号归零 | v1.2.3 → v2.0.0 |
| 功能变更 | 次版本+1，修订号归零 | v1.2.3 → v1.3.0 |
| Bug修复 | 修订号+1 | v1.2.3 → v1.2.4 |

### 4.3 版本记录模板

每个交付物文件末尾应有版本记录：

```markdown
---

## 版本记录

| 版本 | 日期 | 修改内容 | 修改人 |
|------|------|----------|--------|
| v1.0.0 | 2026-03-08 | 初始版本 | [角色名] |
| v1.1.0 | 2026-03-09 | 新增2个镜头Prompt | [角色名] |
| v1.1.1 | 2026-03-09 | 修正错别字 | [角色名] |
```

### 4.4 文件命名规范

```
[交付物名称]_v[版本号].md

示例：
- 人物卡_v1.0.0.md
- 分镜Prompt_v1.2.0.md
- 质检报告_v1.0.1.md
```

## 五、修订统计与分析

### 5.1 统计指标

| 指标 | 计算方式 | 健康阈值 |
|------|----------|----------|
| 返工率 | 返工次数/提交次数 × 100% | <20% |
| 平均修复时间 | 总修复时间/问题数 | <4小时 |
| 一次通过率 | 一次通过数/提交总数 × 100% | >80% |
| 核心项缺陷率 | 核心项缺陷数/核心项总数 × 100% | <5% |

### 5.2 常见修订原因分析

| 原因类别 | 具体原因 | 预防措施 |
|----------|----------|----------|
| 理解偏差 | 对需求理解不一致 | 明确需求文档，增加确认环节 |
| 格式错误 | 未按模板输出 | 使用检查清单，输出前自检 |
| 内容缺失 | 漏掉必填项 | 核心项强制检查，下游验收 |
| 质量不达标 | Prompt质量不够 | 提升Prompt编写能力，参考优秀示例 |
| 一致性问题 | 角色场景不一致 | 建立基准图档案，使用一致性参数 |

### 5.3 统计报告模板


## 七、角色职责

### 7.1 各角色在修订流程中的职责

| 角色 | 职责 |
|------|------|
| 责任角色 | 分析问题、修改交付物、更新版本记录 |
| 验收角色 | 检查修改结果、确认问题修复 |
| 质检合规官 | 复检打分、更新质检检查总表、统计分析 |
| 项目协调员 | 跟踪修订进度、协调资源、处理升级 |

### 7.2 时限要求

| 问题级别 | 修复时限 | 升级时限 |
|----------|----------|----------|
| 🔴 核心项缺失 | 2小时 | 4小时 |
| 🟡 推荐项缺陷 | 24小时 | 48小时 |
| 🟢 可选项缺失 | 不限 | 不适用 |
