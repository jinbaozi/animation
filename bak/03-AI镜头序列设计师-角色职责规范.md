# 角色编排总规范（总入口）

> 状态：已确认 | 版本：v1.0 | 日期：2026-04-04  
> **作用**：本目录唯一总览。具体执行细节以各角色规范为准；冲突时以本文件中的 **Phase 定义、输入包命名、门禁顺序** 为准。

## 1. 范围说明

本套 `optimized/` 规范覆盖从 **小说输入** 到 **VideoPrompt 包 + 试生成静态图素材** 的链路，**不包含** AI 配音导演、AI 成片合成总监 相关环节。


## 5. Phase 输入输出一览

| Phase | 执行角色 | 输入 | 输出 |
|-------|---------|------|------|
| Phase 0 | 品控合规官 | 小说文本、改编要求、目标平台、项目名 | 合规预审报告 |
| Phase 1 | 内容总导演 | 合规通过的小说及相关结论 | 剧本 + **基础分镜执行表** + 人物清单 + 场景清单 |
| Phase 1.5 | 镜头序列设计师 | **基础分镜执行表** + 剧本 + 人物清单 + 场景清单 | **增强分镜执行表** + **序列衔接与继承表** + 场景类型分析等 |
| Phase 2a | 美术技术总监 | **增强分镜执行表** + 序列衔接与继承表 + 人设拆解表 + 场景清单 | **人物四视图 Prompt 包** + **场景资产卡** |
| Phase 2b | 美术技术总监 | 人物四视图 Prompt 包 + 场景资产卡 + 固定关键词包等 | **VideoPrompt 包** + **试生成静态图素材** |

## 6. 输入包组装（编排师强制）

编排师在下发每一 Phase 前，必须凑齐 **该 Phase 输入包**，缺一项不得进入下游。

| 目标 Phase | 输入包必含项 |
|------------|-------------|
| Phase 0 | 小说文本、改编要求、目标平台、项目名 |
| Phase 1 | 合规通过结论、原文、改编要求、Phase 0 问题修正记录（如有） |
| Phase 1.5 | 剧本、基础分镜执行表、人物清单、场景清单 |
| Phase 2a | 增强分镜执行表、序列衔接与继承表、人设拆解表、场景清单 |
| Phase 2b | 已通过门禁的人物四视图 Prompt 包、场景资产卡、固定关键词包、试生成要求 |

**原则**：同名文件多版本时，只下发 **最新已确认** 版本；下游收到的是 **输入包**（路径清单可写在执行追踪报告中），不是零散碎片。

## 7. 质量门禁（放行条件）

| Phase | 放行条件（摘要） |
|-------|------------------|
| Phase 0 | 合规预审通过（品控） |
| Phase 1 | 分镜审核通过（人工确认） |
| Phase 1.5 | 镜头序列自检通过（可 AI 自检 + 品控抽检） |
| Phase 2a | 风格锁定人工确认通过（四视图 + 资产卡） |
| Phase 2b | 试生成校验人工确认通过（VideoPrompt + 试生成静态图） |

未通过门禁，编排师不得创建下游任务；处于 **WAITING_HUMAN_CONFIRMATION** 时，编排师只催办与记录，不代人工拍板。

---

## 8. 编排状态机（摘要）

与 `05-编排师-角色职责规范.md` 第 4 章一致，核心状态包括：

`READY` → `IN_PROGRESS` →（`WAITING_HUMAN_CONFIRMATION` / `PASSED` / `NEEDS_REVISION` / `NEEDS_REDO` / `BLOCKED`）

- **PASSED**：本 Phase 通过，可进入下一 Phase 或最终 `COMPLETED`
- **BLOCKED**：缺输入、P0 违规、超过返工上限等，需解除后再 `READY`

---

## 10. 返工与责任

| Phase 失败 | 责任角色 |
|------------|----------|
| Phase 0 | 品控合规官（配合用户/上游修正材料） |
| Phase 1 | 内容总导演 |
| Phase 1.5 | 镜头序列设计师 |
| Phase 2a / 2b | 美术技术总监 |

每 Phase 返工上限 **3 次**；超限 → `BLOCKED`，输出阻塞问题清单（模板见编排师规范）。
