---

## 1. 执行概述

| 项目 | 内容 |
|------|------|
| Phase | Phase 0 |
| 执行角色 | AI品控合规官 |
| 输入 | 小说文本、改编要求、目标平台、项目名 |
| 输出 | 合规预审报告.md |
| 执行时长 | 约10-30分钟（取决于文本长度） |

---

## 2. 执行前提

- [ ] 用户已提供原始小说文本
- [ ] 用户已明确目标平台（抖音/快手/B站等）
- [ ] 用户已说明改编要求（如有）

---

## 3. 执行步骤

### Step 1: 接收与解析

1. 接收用户提交的原始小说
2. 检查文本格式（UTF-8编码，.txt或.md格式）
3. 记录基本信息：
   - 小说标题
   - 字数统计
   - 章节数（如有）

### Step 2: 合规审核清单

对每一项进行检查，结果记录到 `合规预审报告.md`：

#### 2.1 版权审核

| 检查项 | 通过标准 | 风险等级 |
|--------|---------|---------|
| 原创性 | 原创作品或已获得授权 | CRITICAL |
| 抄袭检测 | 无高相似度内容 | CRITICAL |
| 版权声明 | 明确版权归属 | HIGH |

#### 2.2 敏感内容审核

| 检查项 | 通过标准 | 风险等级 |
|--------|---------|---------|
| 政治敏感 | 无违反四项基本原则内容 | CRITICAL |
| 色情低俗 | 无色情描写 | CRITICAL |
| 暴力血腥 | 无过度暴力描写 | HIGH |
| 违法犯罪 | 无教唆犯罪内容 | CRITICAL |
| 封建迷信 | 无迷信宣传 | MEDIUM |

#### 2.3 平台合规审核

| 平台 | 特殊要求 |
|------|---------|
| 抖音 | 竖屏优先，时长15秒-3分钟 |
| 快手 | 竖屏优先，时长15秒-10分钟 |
| B站 | 横屏/竖屏均可，时长灵活 |
| 微信视频号 | 竖屏优先，1分钟以内最佳 |

#### 2.4 内容质量审核

| 检查项 | 通过标准 |
|--------|---------|
| 叙事完整性 | 有清晰的故事线 |
| 角色完整性 | 主要角色有明确动机 |
| 场景可行性 | 场景可转化为视觉表达 |

### Step 3: 评分标准

对每个维度进行0-10分评分：

```
评分维度：
- 版权合规性：___/10
- 内容安全性：___/10
- 平台适配性：___/10
- 叙事完整性：___/10
- 角色丰满度：___/10
- 场景可行性：___/10

综合评分：___/10
```

### Step 4: 问题分类

| 严重度 | 定义 | 处理方式 |
|--------|------|---------|
| CRITICAL | 阻断性问题，必须修复 | 返回用户修改 |
| HIGH | 重要问题，建议修复 | 提供修改建议 |
| MEDIUM | 一般问题，可选修复 | 标注但不阻断 |
| LOW | 轻微问题，无需处理 | 忽略或优化 |

### Step 5: 生成报告

生成 `合规预审报告.md`，格式见附录A。

## 5. 常见问题处理

### Q1: 发现抄袭嫌疑
```
处理：标记CRITICAL，停止审核，报告用户
```

### Q2: 平台要求与内容冲突
```
处理：提供修改建议，优先级 MEDIUM-HIGH
例：用户想要10分钟内容但目标抖音 → 建议拆分或精简
```

### Q3: 部分章节有问题
```
处理：标注问题位置，允许其他章节继续
```

---

## 6. 返工机制

- **返工触发**：用户修改后重新提交
- **返工上限**：连续3次返工
- **升级处理**：3次后仍无法通过，报告用户无法制作
