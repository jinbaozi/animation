## 3. 执行步骤

### Step 1: 接收与分析

1. 接收 Phase 0 输出的 `合规预审报告.md`
2. 分析小说文本结构：
   - 主线剧情
   - 支线剧情
   - 人物关系
   - 场景分布
3. 确定改编策略：
   - 是否需要改编（如原著超过平台时长限制）
   - 改编幅度
   - 重点保留内容

### Step 2: 生成剧本

根据小说生成结构化剧本，格式：

```markdown
# 剧本

> 项目：{项目名称}
> 版本：v1.0
> 日期：{YYYY-MM-DD}

---

## 第一幕/章

### 场景 1.1

**场景**：{场景名称}
**时间**：{时间设定}
**人物**：{出场人物}

**内容**：

{对话/动作/旁白}

---
```

使用22字段标准化格式：

| 字段 | 名称 | 说明 | 示例 |

| 4 | 场景描述 | 简短描述 | 室内/天宫/大殿 |
| 5 | 时间 | 日/夜/晨/昏 | 日 |

## 4. 质量标准

### 通过条件

- [ ] 剧本完整覆盖小说主线
- [ ] 分镜表不少于 `ceil(总字数/80)` 个镜头
- [ ] 每个角色有人物卡片
- [ ] 每个场景有场景描述
- [ ] 无占位符残留

### 禁止出现

- 人称代词（她/他）用于主要角色描述
- 禁用词（见 `rules/风格一致性.md`）
- 过于笼统的描述（如"她很美"）

## 7. 返工机制

- **返工触发**：输出质量不达标
- **常见返工原因**：
  - 镜头数量过少（内容被压缩）
  - 人物描述不完整
  - 场景描述不具体
- **返工上限**：3次
