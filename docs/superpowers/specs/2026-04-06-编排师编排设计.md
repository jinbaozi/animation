# 编排师编排设计文档

> 状态：v1.0 | 日期：2026-04-06
> 目标：将5个角色文件统一编排入库，实现一键启动自动化流程

---

## 1. 背景与目标

### 1.1 现状问题

| 问题 | 描述 |
|------|------|
| 执行文档超限 | `Phase2-美术技术总监执行指令.md`（291行）超过200行限制 |
| 规则文件超限 | `Seedance2提示词技巧大全.md`（756行）超过400行限制 |
| 缺少一键触发 | 各角色文件缺少统一的自动化启动机制 |
| 与audit-agent不一致 | 审核智能体已有成熟的模块化架构，主力角色未对齐 |

### 1.2 设计目标

1. **统一入库** — 所有角色文件通过编排师统一入口管理
2. **一键启动** — 支持slash命令、对话式、目录监测三种触发方式
3. **文件合规** — 所有直接引用文件≤200行，间接引用文件≤400行
4. **架构一致** — 与audit-agent.md的模块化设计保持一致

## 2. 核心架构

### 2.1 星型通信拓扑

```
                    ┌─────────────────┐
                    │   用户（任务入口） │
                    └────────┬────────┘
                             │
                    ┌────────▼────────┐
                    │      编排师       │
                    │  （唯一通信中枢）   │
                    └──┬──┬──┬──┬──┬──┘
                       │  │  │  │  │
              ┌────────┘  │  │  │  └────────┐
              ▼           ▼  ▼  ▼           ▼
      ┌────────────┐ ┌────────────┐ ┌────────────┐ ┌────────────┐
      │ 品控合规官  │ │ 内容总导演  │ │镜头序列设计师│ │美术技术总监│
      └────────────┘ └────────────┘ └────────────┘ └────────────┘
```

### 2.2 Phase执行链路

```
Phase 0 ──→ Phase 1 ──→ Phase 1.5 ──→ Phase 2a ──→ Phase 2b
（严格顺序执行，上一Phase完成前下一Phase不启动）
```

**执行策略：**
- **Phase内**：同一Phase内的独立子任务并行执行
  - **并行判定标准**：子任务之间**无共享输入**时方可并行
  - 示例：Phase 2a中，多个人物的四视图生成之间无共享输入，可并行；人物四视图与场景资产卡共享"增强分镜执行表"，不可并行
- **Phase间**：严格顺序，上一Phase完全完成后下一Phase才开始
- **数据一致性**：通过缓存层+版本锁定保障

### 2.3 三种触发方式

| 触发方式 | 场景 | 示例 |
|---------|------|------|
| **Slash命令** | 快速启动标准化任务 | `/orchestrate --project=项目名 --novel=小说.txt` |
| **对话式** | 复杂/定制化需求 | "帮我处理这本小说，要突出情感戏" |
| **目录监测** | 自动化流水线 | 检测到 `input/{项目名}/` 有新文件时自动触发 |

## 5. 数据一致性保障

### 5.1 一致性目标

| 目标 | 说明 |
|------|------|
| 不丢数据 | 所有子任务输出都被正确保存 |
| 不冲突 | 并行写入时无数据覆盖 |
| 版本可追溯 | 每个Phase的输入输出版本锁定 |

### 5.2 缓存层设计

```
output/{项目名}/.cache/
├── 人物特征哈希表.json   # 人物一致性校验
├── 场景标签哈希表.json   # 场景一致性校验
└── 版本锁定.json         # 各Phase输出版本锁定
```

### 5.3 冲突检测机制

- **写入前检查**：写操作前检查缓存哈希表，确保无版本冲突
- **版本锁定**：每个Phase完成后锁定输出版本，下游Phase读取时校验
- **人工确认**：版本不一致时触发人工确认，不自动覆盖

> **实施细节**：锁粒度、timeout、merge策略等具体实现方案在实施阶段根据技术栈确定。
