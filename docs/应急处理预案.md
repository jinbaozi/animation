## 1. 返工升级机制

### 1.1 返工次数定义

| 返工次数 | 处理方式 | 责任人 | 升级条件 |
|:---|:---|:---|:---|
| 第1次返工 | 原角色自行修正 | 执行角色 | 输出质量不达标 |
| 第2次返工 | 编排师介入协调 | 编排师 | 修正后仍不达标 |
| 第3次返工 | 提交问题清单+建议方案 | 编排师→用户 | 2次修正后仍有问题 |
| 超过3次 | 标注项目风险，询问用户是否继续 | 用户决策 | 3次后仍无法通过 |

### 1.2 返工触发条件

| 条件类型 | 说明 | 触发动作 |
|:---|:---|:---|
| 质量不达标 | 输出不符合量化验收标准 | 记录问题，触发返工 |
| BLOCK问题 | 发现CRITICAL级别问题 | 立即暂停，报告用户 |
| 规则违反 | 违反项目规则（如禁用词） | 记录问题，触发返工 |
| 用户要求 | 用户主动要求返工 | 按用户要求执行 |

### 1.3 返工流程

```
检测到问题
    │
    ▼
评估问题严重度
    │
    ├─── CRITICAL ───▶ 立即暂停，生成BLOCK报告
    │                      │
    │                      ▼
    │                 通知用户，等待指示
    │
    └─── HIGH/MEDIUM ───▶ 生成阻塞问题清单
                               │
                               ▼
                          发送给对应角色
                               │
                               ▼
                          角色执行修正
                               │
                               ▼
                          验证修正结果
                               │
                    ┌─────────┴─────────┐
                    │                   │
                 通过                不通过
                    │                   │
                    ▼                   ▼
               继续下一Phase      返工次数+1
                                       │
                              ┌────────┴────────┐
                              │                 │
                          ≤3次              >3次
                              │                 │
                              ▼                 ▼
                         返回继续          升级用户决策
```

## 2. 内容严重缺失应急

### 2.1 触发条件

当检测到以下情况时，触发内容严重缺失应急：

| 情况 | 示例 |
|:---|:---|
| 分镜数量严重不足 | 千字小说仅2-3个镜头（应≥12个） |
| 人物描述严重缺失 | 人物清单缺少主要角色 |
| 场景描述严重缺失 | 场景清单缺少核心场景 |

### 2.2 应急处理流程

1. **立即暂停**：暂停后续Phase执行
2. **输出BLOCK报告**：生成[BLOCK]级问题清单
3. **详细说明**：缺失维度分析（哪个Phase、什么问题、多少缺失）
4. **提供建议**：补全建议清单（具体需要补充什么）
5. **等待确认**：用户确认后继续

### 2.3 BLOCK报告格式

```markdown
# [BLOCK] 内容严重缺失报告

| 项目 | 内容 |
|------|------|
| 问题ID | BLOCK-{Phase}-{序号} |
| 严重度 | CRITICAL |
| 触发条件 | 内容严重缺失 |
| 影响Phase | 当前Phase及后续所有Phase |

## 缺失分析

### 分镜完整性
- 理论最低镜头数：{ceil(总字数/80)}
- 实际输出镜头数：{实际数量}
- 缺失比例：{XX%}

### 人物描述完整性
- 人物清单总角色数：{X}
- 有人设拆解的角色数：{Y}
- 缺失：{X-Y}个

### 场景描述完整性
- 场景清单总场景数：{X}
- 有完整描述的场景数：{Y}
- 缺失：{X-Y}个

## 补全建议清单

1. [具体补充建议1]
2. [具体补充建议2]
3. [具体补充建议3]

## 用户确认

□ 已确认问题，同意继续修正
□ 其他指示：___________
```

## 3. 跨Phase反馈异常处理

### 3.1 反馈异常情况

| 情况 | 处理方式 |
|:---|:---|
| 角色无法理解问题 | 编排师提供更具体的修改指引 |
| 角色认为问题不属于己责 | 编排师裁决归属，必要时升级用户判断 |
| 修正后仍不达标（≤2次反馈） | 允许再次反馈，最多2次/问题 |
| 修正后仍不达标（>2次反馈） | 升级为BLOCK问题，暂停流程，等待用户指示 |

### 3.2 反馈循环追踪

| 问题ID | 问题类型 | 来源Phase | 目标角色 | 当前状态 | 反馈次数 |
|:---|:---|:---|:---|:---|:---|
| FEEDBACK-P1.5-001 | 叙事偏离 | Phase 1.5 | AI内容总导演 | OPEN | 1 |
| FEEDBACK-P2A-001 | 视觉可行性 | Phase 2a | AI镜头序列设计师 | IN_PROGRESS | 2 |

## 4. 问题上报流程

### 4.1 上报路径

```
角色发现阻塞问题
    │
    ▼
编排师接收问题
    │
    ▼
编排师分类问题
    │
    ├─── 叙事类问题 ──────────▶ AI内容总导演
    │
    ├─── 镜头序列类问题 ─────▶ AI镜头序列设计师
    │
    ├─── 视觉资产类问题 ─────▶ AI美术技术总监
    │
    └─── 合规类问题 ─────────▶ AI品控合规官
```

### 4.2 上报时间要求

| 问题严重度 | 上报时间 | 处理时限 |
|:---|:---|:---|
| CRITICAL | 立即 | 1小时内响应 |
| HIGH | 24小时内 | 48小时内处理 |
| MEDIUM | 72小时内 | 1周内处理 |

## 5. 超时处理机制

### 5.1 人工确认节点超时

| 节点类型 | 超时时间 | 超时处理 |
|:---|:---|:---|
| 人工确认节点 | 48小时 | 自动提醒通知用户 |
| AI自检节点 | 24小时 | 标记异常待人工介入 |

### 5.2 阶段执行超时

| 阶段 | 预估时长 | 超时阈值 | 处理方式 |
|:---|:---|:---|:---|
| Phase 0 | 10-30分钟 | 2小时 | 报告用户，检查阻塞 |
| Phase 1 | 30-60分钟 | 3小时 | 报告用户，检查阻塞 |
| Phase 1.5 | 30-45分钟 | 2小时 | 报告用户，检查阻塞 |
| Phase 2a | 60分钟 | 3小时 | 报告用户，检查阻塞 |
| Phase 2b | 60分钟 | 3小时 | 报告用户，检查阻塞 |

## 6. 项目终止条件

### 6.1 强制终止条件

满足以下任一条件，项目强制终止：

| 条件 | 说明 |
|:---|:---|
| 超过3次返工仍无法达标 | 用户选择终止 |
| 用户主动要求终止 | 用户决定终止 |
| 核心内容无法补救 | 如小说文本无法改编 |

### 6.2 终止流程

```
触发终止条件
    │
    ▼
生成项目终止报告
    │
    ▼
整理已完成的产出物
    │
    ▼
通知用户
    │
    ▼
归档项目文件
```
