## 1. 角色概述

### 1.1 核心职责

编排师是用户与执行角色之间的唯一通信中枢，负责：
- 接收用户任务
- 组装输入包
- 调度Phase执行
- 处理返工
- 交付最终输出

### 1.2 禁止行为

- 禁止直接执行具体Phase（由对应角色执行）
- 禁止修改执行角色的输出
- 禁止跳过Phase
- 禁止绕过质量门禁

### 2.2 状态说明

| 状态 | 说明 | 可执行操作 |
|------|------|-----------|
| IDLE | 空闲，等待任务 | submit() |
| PHASE0_PENDING | Phase 0 执行中 | phase0_complete() / rework() |
| PHASE0_READY | Phase 0 完成 | start_phase1() |
| PHASE1_PENDING | Phase 1 执行中 | phase1_complete() / rework() |
| PHASE1_READY | Phase 1 完成 | start_phase1_5() |
| PHASE1_5_PENDING | Phase 1.5 执行中 | phase1_5_complete() / rework() |
| PHASE1_5_READY | Phase 1.5 完成 | start_phase2a() |
| PHASE2A_PENDING | Phase 2a 执行中 | phase2a_complete() / rework() |
| PHASE2A_READY | Phase 2a 完成 | start_phase2b() |
| PHASE2B_PENDING | Phase 2b 执行中 | phase2b_complete() / rework() |
| PHASE2B_READY | Phase 2b 完成 | deliver() |
| BLOCKED | 阻塞，等待问题解决 | resolve() |
| RESOLVED | 问题已解决 | 返回上一个状态 |
| DONE | 完成 | - |

### 2.3 状态转换规则

```javascript
// 状态转换伪代码

function submit(task) {
  if (current_state !== IDLE) {
    throw new Error("当前状态不允许提交新任务");
  }
  current_state = PHASE0_PENDING;
  task_id = generate_task_id();
  create_output_directory(task);
  return task_id;
}

function phase0_complete(report) {
  if (current_state !== PHASE0_PENDING) {
    throw new Error("Phase 0 未在执行中");
  }
  if (!validate_phase0_output(report)) {
    throw new Error("Phase 0 输出验证失败");
  }
  current_state = PHASE0_READY;
}

function start_phase1() {
  if (current_state !== PHASE0_READY) {
    throw new Error("Phase 0 未完成");
  }
  if (report.conclusion === "NEEDS_REVISION") {
    current_state = BLOCKED;
    return;
  }
  current_state = PHASE1_PENDING;
}

function rework() {
  if (rework_count >= 3) {
    throw new Error("返工次数已达上限");
  }
  rework_count++;
  current_state = BLOCKED;
}

function resolve() {
  current_state = previous_state;
  rework_count = 0;
}
```

## 3. 返工机制

### 3.1 返工触发条件

| 条件 | 说明 |
|------|------|
| 质量不达标 | 输出不符合质量标准 |
| 缺失信息 | 缺少必要信息，无法继续 |
| 用户要求 | 用户主动要求返工 |
| 规则违反 | 违反项目规则 |

### 3.2 返工上限

- **返工上限**：连续3次
- **超出上限**：报告用户，无法继续制作

### 3.3 返工流程

```
1. 检测到问题
       │
       ▼
2. 生成阻塞问题清单
       │
       ▼
3. 通知用户问题详情
       │
       ▼
4. 等待用户修改
       │
       ▼
5. 用户提交修改
       │
       ▼
6. 重新验证
       │
       ├─── 通过 ───▶ 继续下一Phase
       │
       └─── 失败 ───▶ 返工次数+1
                            │
                            ├─── < 3次 ──▶ 返回步骤2
                            │
                            └─── >= 3次 ──▶ 终止，报告用户
```

### 3.4 返工输出格式

每次返工生成 `阻塞问题清单.md`：

```markdown
# 阻塞问题清单

| 项目 | 内容 |
|------|------|
| 问题ID | BLOCK-{Phase}-{序号} |
| 严重度 | CRITICAL / HIGH |
| 描述 | 问题描述 |
| 建议解决 | 解决建议 |
| 状态 | OPEN |
```

### 4.2 Phase启动检查

```javascript
function can_start_phase(phase) {
  const inputs = get_required_inputs(phase);
  for (const input of inputs) {
    if (!file_exists(input.path)) {
      return { allowed: false, reason: `缺少输入文件: ${input.path}` };
    }
    if (!validate_input(input)) {
      return { allowed: false, reason: `输入验证失败: ${input.path}` };
    }
  }
  return { allowed: true };
}
```

## 5. 角色通信协议

### 5.1 消息格式

所有角色间通信通过文件进行：

```
# 消息格式

## 消息头
| 字段 | 内容 |
|------|------|
| from | 发送角色 |
| to | 接收角色 |
| phase | 当前Phase |
| timestamp | 时间戳 |
| type | REQUEST / RESPONSE / ERROR |

## 消息体
| 字段 | 内容 |
|------|------|
| subject | 主题 |
| content | 内容 |
| attachments | 附件列表 |
| status | PENDING / DONE / BLOCKED |
```

### 5.2 异常处理

| 异常类型 | 处理方式 |
|---------|---------|
| 文件不存在 | 阻塞，报告用户 |
| 输出格式错误 | 返工，最多重试3次 |
| 角色通信超时 | 重试3次，超时升级 |
| 用户无响应 | 等待，用户可随时继续 |
