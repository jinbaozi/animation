# AI审核智能体设计规范

> 本文档定义了AI拟真人短剧审核智能体的完整设计方案。
> 生成时间：2026-04-06
> 状态：APPROVED

---

## 一、问题背景

**当前问题：** AI拟真人短剧制作流程（Phase 0→1→1.5→2a→2b）目前完全依赖人工检查，缺乏系统性的质量审核机制。错误容易逐级传递，导致最终需要重做，效率低下。

**目标：** 构建独立审核智能体，在关键Phase节点自动触发质量审核，拦截错误，保障成片质量。

---

## 二、8大审核维度

| # | 维度 | 核心校验内容 | 规则引擎 | LLM |
|---|------|-------------|---------|-----|
| D1 | 人物一致性 | 面部特征、体型、服装、配饰与定版卡100%匹配 | ✅ 特征关键词 | ✅ 复杂判断 |
| D2 | 场景一致性 | 背景布局、光照、色调、道具与前序镜头匹配 | ✅ 场景标签 | ✅ 空间逻辑 |
| D3 | 动作连贯性 | 肢体动作、物体交互、物理真实性 | ✅ 时间戳 | ✅ 物理判断 |
| D4 | 剧情符合度 | 分镜任务完成度、情绪递进、伏笔回收 | ✅ 任务标签 | ✅ 叙事逻辑 |
| D5 | 表情精准度 | 微表情、面部肌肉状态、眼神细节 | ✅ 表情关键词 | ✅ AU动作单元 |
| D6 | 对戏互动 | 多角色视线、站位、肢体接触、情绪传染 | ✅ 站位标签 | ✅ 交互逻辑 |
| D7 | 运镜专业度 | 景别、运镜方式、摄像机运动、光影 | ✅ 参数范围 | ✅ 叙事服务 |
| D8 | 世界观合规 | 时代背景、文化细节、物理规则、题材禁忌 | ✅ 违禁词正则 | ✅ 设定僭越 |

## 三、Scope划分

### MVP范围（推荐先行）

- 仅在Phase 2b（最终VideoPrompt输出）前触发一次完整审核
- 覆盖8大审核维度（规则引擎预筛 + LLM细审）
- 输出分级报告（Markdown格式）
- 作为建议性质（非强制门禁）

### 全量范围（后续扩展）

- 每个Phase结束后都触发审核（Phase 0→1→1.5→2a→2b）
- 强制门禁机制（P0阻断进入下一Phase）
- 审核结果导出和追踪系统
- 向量数据库相似度比对（可选）

---

## 四、核心约束

1. **深度优先原则** — 宁可审核时间长一点，也要每个维度都查到位
2. **混合架构** — 规则引擎做初筛 + 大模型做细审，兼顾效率与深度
3. **问题分级** — P0（阻断性）、P1（显著瑕疵）、P2（优化项）
4. **LLM成本约束** — 仅在规则引擎标记为"疑问"时调用LLM，避免全量调用

---

## 五、架构设计

### 审核流程

```
Phase 2b输出 → 规则引擎（8维度并行检查）
    ├─→ 全部通过 → LLM细审（仅验证，无新增问题）→ 报告：通过
    ├─→ 部分疑问 → LLM细审（仅疑问维度）→ 报告：建议修改
    └─→ 发现P0 → 直接输出P0报告 → 报告：阻断性错误
```

### 与Phase流程的交互

```
用户提交任务
    │
    ▼
┌─────────────────────────────────────────────┐
│  Phase 0→1→1.5→2a→2b  (现有流程)          │
└─────────────────────────────────────────────┘
    │
    ▼ Phase 2b 完成后
┌─────────────────────────────────────────────┐
│  审核智能体（独立Agent）                      │
│    │                                        │
│    ├─→ 规则引擎预检（8维度结构化检查）        │
│    │       │                                │
│    │       ├─→ 通过 → LLM细审（仅标记疑问）  │
│    │       │       │                        │
│    │       │       └─→ 汇总 → 分级报告      │
│    │       │                                │
│    │       └─→ 疑问 → LLM细审（全维度）     │
│    │               │                        │
│    │               └─→ 汇总 → 分级报告      │
│    │                                        │
│    └─→ 输出：审核报告.md                     │
└─────────────────────────────────────────────┘
    │
    ▼
编排师/AI导演 根据报告决定是否返工
```

### 触发机制

在Phase 2b完成后，通过调用 `audit-agent.sh` 脚本触发审核：

```bash
./audit-agent.sh --phase=final --input=output/phase2b/ --output=output/audit-report.md
```

## 八、成功标准

### 当前基准

- 人工检查平均耗时：约2-3小时/项目
- 人工检查覆盖率：约60%
- P0错误发现率：约70%

### 目标

1. **效率提升** — 人工检查时间减少50%以上（目标：≤1.5小时/项目）
2. **规则覆盖率** — 规则引擎覆盖100%已定义的P0/P1模式
3. **LLM召回率** — LLM细审能识别出规则引擎遗漏的至少80%额外问题
4. **报告完整性** — 每次审核生成Markdown报告，包含问题定位、维度分类、严重等级、修改建议
5. **可执行性** — 报告中的修改建议可直接用于提示词优化
